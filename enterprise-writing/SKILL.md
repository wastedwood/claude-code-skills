# 企业文书写作

## 工作流程

```
用户提出需求
    ↓
0. 引导建立项目结构规范 → 首次接触该项目时，引导用户在项目目录下创建/确认 CLAUDE.md
   - 确认当前项目目录是否存在 CLAUDE.md
   - 若不存在：引导用户创建，内容包括本项目常见文种的结构骨架、章节顺序、各节字数要求、特定格式规范等
   - 若已存在：读取并遵循其中的结构模板和特殊要求
   - 后续写作全程以该 CLAUDE.md 的结构模板为准
    ↓
1. 识别文种（A-G）→ 无法确定则向用户确认
    ↓
2. 加载对应该文种的语言风格参考（参见对应 references/ 文件）
    ↓
3. 提取已有信息并核实数据时效性
    - 从企业数据表（CSV）提取结构化数据
    - 若用户提供了"之前的材料""参考材料""此前申报书"等历史文档作参考，**不可直接使用**：从中提取关键数据项（从业时间、专利数量、荣誉列表、排名、奖项、项目进度等），逐项列出并请用户确认是否需要更新
    - 列出缺失信息请用户补充
    ↓
4. 生成大纲 → 用户批准
    ↓
5. 逐节写作正文（MD 展示）→ 用户审阅修改
   - 字数受限段落（"XX字以内"），写完后用脚本统计验证，不可凭感觉估算
   - 检查是否覆盖了用户提到的所有要点，避免遗漏
    ↓
6. 内容生成完成，按项目规则保存到指定目录
```

## 防编造红线

以下信息**只能**从用户的企业数据表或对话中读取，绝不可推测或编造：

| 类别 | 来源 |
|------|------|
| 企业名称、成立时间、地址、注册资本、法人 | 数据表 |
| 销售收入、利润、税收、研发费用、资产数据 | 数据表 |
| 产品技术参数（功率、效率、电压等） | 数据表或对话 |
| 获奖名称、年份、级别、排名 | 数据表 |
| 客户名称、项目名称、合作内容 | 数据表或对话 |
| 政策/标准名称及编号 | 用户提供的准确名称 |
| 榜单方向、指南方向等政策性方向名称 | 官方文件或用户明确提供，不可自行组合 |
| 人员姓名、学历、职称、履历 | 数据表或对话 |

允许模板化的内容：过渡句、收尾语、管理机制描述、段落结构框架。
**缺失信息用 `[待补充：XX信息]` 占位，不编造。**

**参考材料数据不可直接照搬**：用户提供的历史申报书、参考材料中的技术参数（效率、电压、功率等数值），必须逐项列出请用户确认是否适用于当前项目，不可默认沿用。政策/标准名称需用户确认准确名称和编号。**技术指标数值的出处必须能在对话或数据表中追溯到，否则空着等用户补充。**

**时间性任务需核实日期来源**：涉及"最新的""截至X月""今年"等时间敏感表述时，必须确认数据源或事件的实际日期，不可根据对话时间自行推算。
**扩展元素有依据才保留**：附件、图片、注释、附注、版记等扩展内容，只在用户明确要求或有数据源支撑时才添加，默认不附加。

```

│   └── → B 科技项目申报书
├── "人才""领军人才""泰山产业""拔尖人才""蓝色专项"
│   └── → D 人才申报书
├── "自评""绩效""中期评估""验收报告""抽查"
│   └── → F 绩效评价报告

```

## 语言风格速查

通用底线：正式书面语、不口语、数据说话、禁用感叹号/网络用语/"众所周知"等空话。

| 文种 | 语体 | 关键特征 |
|------|------|----------|
| A 发言稿 | 口头书面语 | "公司+动词"中句，数据点缀，致谢结尾 |
| B 科技申报书 | **学术论证体** | 计划语态（"拟解决""拟开展""旨在"），问题→分析→路径三段句，术语不加注，禁用口语承转。**需求目标（研究内容）**采用"一句到底、分号串联"结构：针对XX需求，研究XX，突破XX，解决XX问题，实现XX目标；研究XX，形成XX方案；研究XX，突破XX（通过XX方法），实现XX目标；开发XX产品，突破XX技术——动词具体多样（突破、攻克、构建、研发、实现等），避免通篇"提升XX水平" |
| C 平台申请 | 战略叙事体 | 引领体并列排比，管理机制占25-30% |
| D 人才申报 | 个人履历体 | 人称切换（申报人→本人），首创体，排名证据 |
| E 典型案例 | 经验提炼体 | 动宾对仗标题，一是/二是/三是，把事件升华为方法论 |
| F 绩效评价 | **对照完成体** | 完成时（"已完成""达到了"），承诺vs兑现对照 |
| G 资质认定 | 市场推理体 | 宏观→中观→微观逻辑链，市场界定→规模测算→占有率排名 |

## 标题与层级编号

- 一级：`一、二、三、四...`（加粗）
- 二级：`（一）（二）（三）...`
- 三级：`1. 2. 3.`
- 四级：`（1）（2）（3）`
- 不用 `•` 项目符号，改用"一是...二是...三是..."

- 交互环节：Markdown 展示
- 最终交付：按项目规则输出 Markdown 文件

## 字数统计方法

字数受限段落写完后，用以下 Python 脚本验证，不可凭感觉估算：

```bash
python -c "
with open('文件路径.md', 'r', encoding='utf-8') as f:
    text = f.read()
lines = text.strip().split('\n')
body = '\n'.join(lines[1:])        # 去掉首行标题
body_clean = body.replace('\n', '').replace('\r', '').replace(' ', '')
print(f'正文字数: {len(body_clean)}')
"
```

**规则：**
- 统计范围：中文字符、数字、标点、英文字母均计为 1 字，与政府表单计数方式一致
- 不含：标题行（首行）、换行符、空格
- 包含：`一、二、三` 等节标题（属于正文内容）
- 若正文不含独立标题行（即首行就是正文），用 `lines[0:]` 替代 `lines[1:]`

# 高企申报填表助手 — 研发费用结构明细表

## 工作模式：手动 → 自动渐进

本技能采用**渐进式自动化**策略：先手动协作建立信任，再主动问用户要不要切自动挡。

### 第一阶段：手动协作（默认）

前几轮让用户控制导航，AI 只负责填数，让用户建立对数据准确性的信任：

| 谁做 | 做什么 |
|------|--------|
| **你（用户）** | 登录系统 → 进入申报书 → 点「修改」进编辑页 → 审核合计 → 点「保存」→ 开下一个 |
| **AI（我）** | 读取 Excel 数据 → 识别列对应关系 → 填入表单字段 → 触发自动计算 → 读出合计值供你核对 |

**手动协作流程：**
```
你: 打开RDxx编辑页 → 告诉我编号
我: 填数 → 触发计算 → 报合计
你: 审核 → 保存 → 开下一个 → 告诉我编号
↻ 循环
```

### 第二阶段：询问切换自动挡

当手动协作顺利进行了 3-5 次后（用户已看到数据填得准确），主动询问：
> "数据都准确吧？要不要切到**自动挡**？接下来我帮你自动点修改、填数、校验、保存，一步到位，你看着就行。"

用口语化的方式问，不要搞成正式确认弹窗的感觉。

### 第三阶段：自动挡

用户同意后，AI 全权操作：
1. 在列表页找到下一个要修改的 RD 项目 → 点击「修改」 → 进入编辑页
2. 填入数据 → 触发计算 → 校验合计
3. 点击「保存」 → 等页面回到列表 → 自动开始下一个
4. 中途如果遇到翻页、年份切换等操作，一并自动处理
5. 每个项目完成后简要汇报进度（"RD27 完成，合计 123.45 ✅，继续 RD28…"）

**自动挡退出条件**：
- 用户随时说"停"或"我来" → 回到手动模式
- 遇到异常（字段找不到、保存失败等）→ 暂停并告知用户，由用户决定继续手动还是排查问题

**用户 Excel 的表头命名可能和系统字段名不完全一致**，必须先读取第一行（表头），根据语义匹配确定每列对应哪个表单字段。不要假设列的顺序或列名与系统完全一致。

3. 如果某个字段在 Excel 中找不到对应列，则跳过该字段（不修改）
4. 向用户确认识别结果后再开始填写

### 填写策略

哪些字段需要修改取决于 Excel 数据，**不是固定的 5 个**。原则是：

1. Excel 中值不为 0 的字段 → 必须填入
2. Excel 中值为 0 且页面也为 0 的字段 → 不动
3. 页面已有值但与 Excel 不一致的字段 → 用 Excel 值覆盖

所有表单字段的 ID 见上方映射表（`ryrg`、`zjtr`、`zjfy`、`wxzc`、`sjf`、`sbtsf`、`qtfy`、`wtwbyjkftr`、`pjnwbtrhj`），逐一检查、逐一填入。

### 数据单位

系统以 **万元** 为单位，Excel 数据也以万元为单位，直接填入无需换算。

## 技术细节

### 页面结构（iframe 嵌套）

```
主页面
├── div#left（左侧导航）
└── iframe#mainFrame（内容区）
    ├── 顶部标签栏（填报说明、申请书封皮…）
    └── iframe#innocomFrame（表单内容区）
        ├── 列表页（RD 项目表格）
        └── 编辑页（单个 RD 项目的表单）
```

CDP eval 操作需逐层穿透 iframe：

```javascript
// 获取编辑页表单字段
var f = document.getElementById("mainFrame");
var d = f.contentDocument || f.contentWindow.document;
var i = d.getElementById("innocomFrame");
var c = i.contentDocument || i.contentWindow.document;

// 操作表单字段
c.getElementById("ryrg").value = "69.97";
```

### 修改链接定位

在列表页中，每个 RD 项目的「修改」链接格式：
```html
<a href="/xonlinereport/inforeport/DataInnocom/addDataEprRdFee.do?id=XXX&year=2023&">修改</a>
```

**导航到编辑页**（通过修改 iframe 的 src）：
```javascript
i.src = "/xonlinereport/inforeport/DataInnocom/addDataEprRdFee.do?id=XXX&year=2023&";
```

**获取所有修改链接**（用于批量定位）：
```javascript
var els = c.querySelectorAll("[href*=\"RdFee\"]");
```

### 触发自动计算

填入字段后，需调用页面的计算函数才能得到合计：
```javascript
c.defaultView.nbyjkfhj();
```

### 读取合计值

计算后读取只读字段验证：
```javascript
var total = c.getElementById("nwhj").value;
// total 就是"研究开发费用（内、外部）小计（万元）"
```

### 保存操作

优先用点击保存按钮的方式：
```javascript
c.getElementById("dataEprRdfeesave").click();
```

如果点击不生效（页面无响应），改用直接提交表单：
```javascript
var form = c.getElementById("dataEprRdfeeForm");
form.submit();
```

## 协作流程（分步）

### 第一步：读取数据

1. 用户提供 Excel 文件路径（`@/path/to/file.xlsx`）
2. 使用 officecli 读取 Excel 内容：
   ```bash
   officecli view "<file>" text --json
   ```
   或
   ```bash
   officecli get "<file>" '<SheetName>' --depth N --json
   ```
3. 提取各年度各 RD 项目的 5 个核心字段值，建立数据字典

### 第二步：确认起点

确认用户已完成哪些项目、从哪个 RD 项目开始。例如：
> "2023年 RD01-RD25 已填好，从 RD26 开始"

### 第三步：循环填表

每轮循环中，AI 需要**主动判断用户已到达编辑页**，而不是等用户报编号。用户可能说"好了"、"下一个"、"继续"、"34"或者什么都没说只是点了修改——多种情况都表示"页面上准备好了，可以填了"。

识别用户已就绪的信号：
- 用户明确报了一个 RD 编号（如 "26"、"34"）
- 用户说了"好了"、"可以了"、"继续"、"下一个"等
- 用户没说任何话，但感知到页面已经切换到编辑页（通过检查 iframe 内容判断）

无论用户以什么方式示意，AI 的响应都是：
1. 如果用户报了编号 → 查找对应数据填入
2. 如果用户没报编号 → 通过页面上的项目编号下拉框（`xmbh`）当前选中的值来确定是哪个 RD 项目，再匹配数据填入
3. 逐一将 Excel 数据填入表单字段
4. 触发 `nbyjkfhj()` 自动计算
5. 读合计值并对比 Excel
6. 向用户报告填入结果和合计校验情况
7. 等待用户审核后保存，继续下一个

### 第四步：校验

每次填写后必须确认合计值与 Excel 一致。如果出现 0.01 的尾差（Excel 浮点精度导致），如实告知用户即可。

## 已知陷阱与经验

1. **年份切换**：列表页顶部有年份标签（如「2025 2024 2023」），点击后加载对应年份数据。程序化点击可能因页面事件绑定方式不同而失败，此时让用户手动点击即可。
2. **分页**：项目较多时会分页（默认每页 10 条）。可以调为每页 50 条减少翻页，但保存后会重置为默认值。
3. **负值**：费用字段可能出现负数（如冲减前期费用），属于正常数据，按实际值填入即可。
4. **Uncaught 错误**：操作内层 iframe 时偶尔出现 `Uncaught` 错误，通常是页面还在加载或 iframe 导航冲突。等待 2-3 秒后重试即可恢复。
5. **保存不生效**：点击保存按钮后页面仍停留在编辑页，说明提交未触发。改用 `form.submit()` 直接提交表单。
6. **保存后列表状态重置**：保存成功后回到列表页，但年份、页码、每页条数等筛选条件会重置为默认值。
7. **字段读取为 null**：编辑页表单字段全部为 null，说明 iframe 内容尚未完成加载。等待后重新设置 iframe 的 src 重试。
8. **页面提示条**：列表页顶部有"是否默认隐藏提示"的开关，不影响数据操作。
